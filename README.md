# 名刺管理アプリ

営業担当者が受け取った名刺の画像をAIで読み取り、確認・修正してから登録し、後で氏名・会社名で探せるWebアプリです。1組織で使うシングルテナント構成で、PCのブラウザーでの利用を想定しています。

利用の流れは、名刺画像の取り込み、AIによる読み取り、利用者による確認・修正、登録、検索・連絡先の確認です。AIの読み取り結果は、利用者が画像と見比べて「登録」を押すまで保存しません。

## 1. 環境の立ち上げ

### 前提環境

- Python 3.9以上（macOS 26.6 の Python 3.9.6 で確認しました）
- 採用担当者から提供されたLLMのAPIキー（Claude・GPT・Geminiのどれでも動きます）

### 依存関係の導入

```bash
git clone <このリポジトリのURL>
cd <リポジトリのフォルダ>
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### 環境変数

値はリポジトリに含めていません。起動する人がシェルで設定します。

| 変数 | 必須 | 意味 |
|---|---|---|
| `LLM_API_KEY` | 必須 | 採用担当者から提供されたAPIキー。サーバー側だけで使い、ブラウザーには送りません |
| `ADMIN_EMAIL` | 初回のみ | 初期adminのメールアドレス。データベースにadminがいないときだけ使います |
| `ADMIN_PASSWORD` | 初回のみ | 初期adminのパスワード（8文字以上） |
| `LLM_PROVIDER` | 任意 | `anthropic`・`openai`・`gemini` のどれか。空ならキーの先頭（`sk-ant-`、`sk-`、`AIza`）から判定します |
| `LLM_MODEL` | 任意 | 使うモデル。空なら `claude-opus-5-5`・`gpt-5`・`gemini-2.5-flash` を使います |
| `DATA_DIR` | 任意 | データの保存先。既定は `./data` |
| `SECRET_KEY` | 任意 | セッションの署名鍵。空なら初回に `data/secret_key` を作って使い続けます |
| `PORT` | 任意 | 待ち受けのポート。既定は 8000 |

### 起動

`start.sh` は、未設定の値をその場で聞きます。キーとパスワードは画面に表示されず、ファイルにも残りません。

```bash
PYTHON=.venv/bin/python bash start.sh
```

環境変数を先に設定しておけば、何も聞かれずに起動します。

```bash
export LLM_API_KEY=...        # 提供されたキー
export ADMIN_EMAIL=you@example.com
export ADMIN_PASSWORD=...     # 8文字以上
.venv/bin/python -m flask --app app run --port 8000
```

ブラウザーで http://127.0.0.1:8000 を開きます。macOSではポート5000をAirPlayが使うことがあるため、既定を8000にしています。

## 2. 使用技術・AIモデル・対応画像形式

| 区分 | 内容 |
|---|---|
| 言語・フレームワーク | Python、Flask、Jinja2（サーバー側でHTMLを組み立てます） |
| 保存 | SQLite（`data/app.db`）と画像ファイル（`data/images/`） |
| 画像の検査・縮小 | Pillow |
| LLMの呼び出し | Claudeは公式SDK（anthropic）、GPTとGeminiはhttpxでREST APIを直接呼びます |
| 既定のモデル | Claude `claude-opus-5-5`、GPT `gpt-5`、Gemini `gemini-2.5-flash` |
| 対応画像形式 | JPEG・PNG・WebP、1枚5MBまで。HEICは、JPEGに書き出してから取り込みます |

画像の形式は拡張子ではなく中身で判定し、対応しない形式は取り込み画面で理由を表示して断ります。

## 3. 利用者と閲覧権限

### 初期adminの設定

初回の起動時に `ADMIN_EMAIL` と `ADMIN_PASSWORD` からadminを1人作ります。adminが1人でもいれば、2回目以降の起動ではこの2つを使いません。

### 利用者の追加

1. adminでログインし、上部の「利用者と閲覧許可」を開きます。
2. メールアドレスと初期パスワード（8文字以上）を入れて「追加」を押します。role は user で作ります。
3. 初期パスワードは本人に直接伝えます。招待メールは送りません（課題で任意とされているため）。

### 確認用アカウントの使い方

評価する方の手元ではデータベースが空から始まるため、次の手順で確認用の利用者を作ります。

1. 初期adminでログインし、上の手順で一般利用者を2人追加します（例 `user1@example.com`、`user2@example.com`）。
2. 別のブラウザー（またはシークレットウィンドウ）で user1 としてログインし、名刺を登録します。
3. user2 でログインすると、user1 の名刺は一覧に出ず、詳細や画像のURLを直接開いても「Not Found」になります。
4. adminが user2 に企業・部署・人物の許可を付けると、その範囲だけが user2 に見えるようになります。

### role と閲覧許可

- role は users テーブルの `role` 列（`admin` か `user`）で持ちます。画面から role を変える機能はありません。
- adminは、登録者に関係なくすべての名刺を閲覧できます。
- userは、自分が登録した名刺と、adminが許可した範囲の名刺を閲覧できます。どれか1つを満たせば閲覧できます。
- adminは「利用者と閲覧許可」で利用者ごとに「確認・変更」を開き、許可の確認・付与・解除を行います。同じ画面に、その利用者が今閲覧できる名刺の一覧も出します。

| 許可の単位 | 選び方 | 判定 |
|---|---|---|
| 企業 | 登録済みの会社名から選ぶ | 会社名が一致する名刺 |
| 部署 | 登録済みの「会社名と部署名の組」から選ぶ | 会社名と部署名の両方が一致する名刺 |
| 人物 | 登録済みの名刺から1枚選ぶ | その名刺だけ |

## 4. 設計上の判断と仮定

| 判断 | 理由 |
|---|---|
| 権限の判定を1か所（`access.py`）にまとめ、一覧・検索・詳細・画像のすべてがそこを通る | 画面ごとに判定を書くと、どれか1つで漏れるため。権限が無い名刺も存在しない名刺も、同じ404を返します |
| 部署の許可は「会社＋部署」の組で持つ | 別会社の同名部署（例 どちらも「営業部」）に許可が広がらないようにするため |
| 人物の許可は名刺1枚（名刺ID）で持つ | 同姓同名の別人に広がらないようにするため。同じ人の新しい名刺を登録したときは、許可を付け直す必要があります |
| 会社名・部署名の照合は、全角半角・空白の数・英字の大小だけをそろえる | 「ＡＢＣ商事」と「ABC商事」は同じと見なします。「ABC商事」と「ABC商事株式会社」は別と見なします。あいまいに一致させると、意図しない会社に許可が広がるためです |
| 許可の対象は、自由入力でなく登録済みの名刺から選ぶ | 打ち間違いで、誰にも当たらない許可を作らないため |
| 登録者は、ログイン中の利用者をサーバー側で記録する | フォームの値を使わないので、登録者を偽れません。role もリクエストのたびにデータベースから読みます |
| AIの読み取り結果は保存せず、確認画面で「登録」を押したときだけ保存する | AIの誤りを人が直してから残すため |
| LLMには文字の書き起こしだけを任せ、形式の確認はPythonで行う | メールアドレス・電話番号・URLの形式と氏名の有無を、コードで確かめて画面に注意を出します |
| 名刺に無い項目は空欄にするよう指示し、推測での補完を禁じる | 課題の要件のため。AIが読み取りに自信の無い項目は、確認画面で色を付けます |
| 名刺に書かれた文はデータとして扱い、そこにある指示には従わないようLLMに指示する | 画像の中の文で動作を変えられないようにするため |
| LLMに送る画像は長辺1568pxに縮める（保存するのは元の画像） | 大きな写真ほどトークンが増えるため |
| 読み取りに失敗しても、取り込んだ画像は残し、再読み取りか手入力で登録できる | 課題の「失敗時の案内」のため |
| フォームの送信にはCSRFトークンを付ける | 別のサイトから、ログイン中の利用者に許可の付与などを送らせないため |
| パスワードは pbkdf2-sha256 でハッシュ化する | macOS標準のPython 3.9では scrypt が使えないため |

## 5. 動作確認

### 自動テスト（pytest）

LLMは差し替え、ネットワーク無しで動きます。

```bash
.venv/bin/python -m pytest -q tests
```

結果：**24 passed**（2026-11-10、macOS・Python 3.9.6）。確かめている内容は次のとおりです。

| 区分 | 確かめていること |
|---|---|
| ログイン | 初期adminがログインできる。未登録のメールアドレスではログインできない。ログアウト後は一覧を開けない |
| 閲覧権限 | 許可の無いuserは自分の名刺だけを見る。adminはすべてを見る |
| 閲覧権限 | 別会社の同名部署、同姓同名の別の名刺、会社名が空の名刺には許可が広がらない |
| 閲覧権限 | 許可を1つ解除しても、別の許可や登録者としての権限が残れば見える。利用者を識別できなければ何も見えない |
| 直接のURL | 他人の名刺の詳細・画像・検索結果・取り込み途中の画像を、URLを直接指定しても取得できない |
| admin専用 | userは利用者の追加と許可の付与ができず、自分に許可を付けられない |
| 登録 | 読み取り結果は登録前に保存されない。修正した値で保存され、登録者はログイン中の利用者になる。フォームで登録者を偽っても無視される |
| 失敗時 | キーが無いなど読み取りに失敗しても、手入力で登録できる。氏名が空なら登録できない。画像でないファイルは断る |
| 永続化 | アプリを作り直しても（再起動に相当）、名刺と利用者が残る |
| AIの出力 | 項目の欠け・文字列でない値・不正な項目名を空欄にそろえ、注意を出す。キーの先頭から会社を判定する |

## 6. 制約・未実装・未確認
